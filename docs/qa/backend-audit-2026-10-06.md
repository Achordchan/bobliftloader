# 后台覆盖与结构审查（GPT-6，2026-10-06）

**结论：后台尚未覆盖全部前台内容，而且存在“后台可编辑、REST 保存却丢数据”的高优先级问题。** 目前结构化编辑器覆盖首页、采购与售后、应用场景、滑移装载机、迷你翻斗车这 5 个入口；关于、联系、隐私、全站公共内容，以及多个页面的区块标题、按钮、说明和链接仍有覆盖缺口。

本报告基于当前仓库，已遍历全部前台 PHP 模板、内容读取函数、后台字段及保存逻辑、REST 注册和后台 CSS/JS。REST = 外部程序通过接口读取或修改内容；下文的 REST 可读写均指具备权限的请求，`context=edit` 限制本身不算缺陷。没有修改文件、连接生产数据库、提交表单或执行浏览器验证；WordPress.com 线上插件提供的额外接口不在已验证范围内。

## A 覆盖缺口（前台有后台无）

以下将同一区块中共用同一缺失编辑入口的文字、图片和链接合并列出；自动从产品数据计算的数量、参数和日期，不另列为缺口。

## B REST 缺口

1. **【高】新增型号装柜数据在 REST 中不可完整读写，修改其他字段也可能丢失。**  
   **位置：** `inc/wp-rest.php:208`、`inc/wp-rest.php:262`、`inc/editable.php:479`、`inc/editable.php:471`。  
   **问题：** `bl_merge_content()` 忽略默认结构以外的键。前台另外补回新增型号的装柜数据，但 REST 读取和保存没有补回。内存复核：后台已有 `new-machine: [3,7]` 时，前台读取正常，REST 读取缺失；仅修改 Support 小标题，待保存结果也不再包含该型号数据。  
   **建议：** 对装柜数据使用允许动态型号键的明确结构，并让后台、前台、REST 共用同一套读取及合并规则。

2. **【高】首页旧公司数据迁移只作用于前台/编辑器读取，未作用于 REST。**  
   **位置：** `inc/editable.php:452`、`inc/editable.php:468`、`inc/wp-rest.php:208`、`inc/wp-rest.php:263`。  
   **问题：** 旧 `intro.facts` 在前台会迁到 `approach.facts`，REST 却显示默认公司数据。内存复核中，前台显示旧保存值 `40,000`，REST 返回默认 `37,000`；随后通过 REST 修改无关标题，会将旧数据从待保存结果中移除。  
   **建议：** 所有读取/写入入口先经过同一版本迁移，再进行合并和差异保存。

3. **【中】下载画册后台可改，REST 没有对应读写入口。**  
   **位置：** `inc/wp-support.php:92`、`inc/support.php:48`。  
   **问题：** `bl_catalogue_url` 只在 `admin_init` 注册，未启用 `show_in_rest`；`bl_catalogue_size` 也未暴露。上传媒体文件不等于能通过接口替换前台画册。  
   **建议：** 将设置注册移至 REST 请求也会执行的入口，提供受权限保护的读写；文件大小保持自动计算、只读返回。

4. **【中】新闻作者职位后台可改，REST 无法读写。**  
   **位置：** `inc/wp-admin.php:378`、`inc/wp-admin.php:387`、`inc/wordpress.php:78`。  
   **问题：** `bl_title` 直接存入用户扩展字段，没有 `register_user_meta()` 或自定义 REST 字段注册。  
   **建议：** 注册类型、清洗规则和编辑权限；同时补齐上一组提到的新闻作者支持。

5. **【中】案例 `image` 字段接口允许写入，但前台不会使用。**  
   **位置：** `inc/wp-rest.php:48`、`inc/wp-rest.php:58`、`inc/wordpress.php:108`。
